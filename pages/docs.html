Go-live checklist

Finish these steps in Test mode. When the first three are done, request a go-live review and your account manager switches on Live payments.

    Authentication

    Every call goes to one base URL and carries your API key in the X-Api-Key header. The key is your key ID and secret joined by a dot. Requests and responses are JSON, and money is always a decimal string such as "25.00", never a JSON number.

    Base URL
    https://pay-api.the-block.com
    Header
    X-Api-Key: <keyId>.<secret>
    Content type
    application/json

    Test and Live keys are separate. Create them on API keys. Keep secrets on your server; never ship them in a browser or mobile app.

    Offerings

    Everything you can do is an offering, named PROVIDER.PRODUCT.VARIANT.ACTION. The action is one of PAYIN, PAYOUT, CANCEL, REFUND or QUERY.

    An offering is the whole contract: currencies, minimums and extra fields. Read offerings from GET /offerings at runtime and never hard-code them.

    Create a payment

    Send POST /payments with an offering, your own unique requestId, an amount and a currency. The response tells you what the customer does next, such as opening a hosted card page or paying to a deposit address.

    Reusing a requestId returns 409. A prefix such as ORD- or WD- keeps them unique across pay-ins and payouts.

    Statuses

    Every payment has one status. Treat only PAID as money received, and stop polling once a status can no longer change.

    StatusMeaningCan it still change?
    PENDINGCreated; the outcome is not known yetYes
    PAIDFunds received and confirmed by the providerOnly by a refund
    FAILEDThe provider refused it or it expiredNo
    CANCELLEDCancelled by you or by the providerNo

    Webhooks

    We send payment.status_updated to each subscribed endpoint when a status changes. Each delivery is signed with your endpoint's signing secret in the X-Signature header (HMAC SHA-256 of the timestamp and raw body). We retry up to 5 times, then dead-letter the event. You can have up to 10 endpoints.

    Manage endpoints and send test events on Webhooks.

    Cards

    Card programs run through three issuers: Axys, Hypercard and Interlace. To create cardholders and order cards, your API key needs the CARDS scope; a key without it gets 403 FORBIDDEN_SCOPE.

    • card_order.status_updated follows a card order from submitted to shipped.
    • cardholder.status_updated reports KYC review results.

    Add the scope when you create a key on API keys. Finance members never see API keys.

    Errors

    Errors return an HTTP status and a JSON body with a stable code and a readable message. Retry only 429 and 5xx, with backoff.

    HTTPCodeWhat to do
    400VALIDATION_ERRORFix the field named in details
    401UNAUTHORIZEDCheck the X-Api-Key header and the key's mode
    403FORBIDDEN_SCOPEAdd the missing scope to the key
    404PAYMENT_NOT_FOUNDCheck the requestId
    409DUPLICATE_REQUEST_IDUse a new requestId, or read the existing payment
    409PAYMENT_NOT_CANCELLABLEOnly PENDING payments can be cancelled
    422OFFERING_UNAVAILABLERe-read offerings; this one is off for your account
    429RATE_LIMITEDWait for Retry-After, then retry
    502PROVIDER_UNAVAILABLERetry with backoff; check System status on Contact support
